# Legacy CPV converter (Python port)

This folder contains an isolated Python port of the original converter from:

- Repository: [friedrichOsDev/cp400-cpv-player](https://github.com/friedrichOsDev/cp400-cpv-player)
- Original source: `src/pc/main.c`
- Original format declarations: `src/pc/cpv.h`

It is deliberately separate from the modern CPV v1.3 implementation. It does not modify or import the v1.3 `convert.py`, `play.py`, or `cpv_v1.md`.

## What it reproduces

The output is the original **legacy CP format**, not CPV v1.0–v1.3.

The port preserves the original:

1. Six-byte `CP` header: magic, 8-bit width, 8-bit height, FPS/flags byte, reserved byte.
2. Fixed 256-entry RGB565 palette (512 bytes), generated by FFmpeg.
3. The 6×6 / 108-byte seed image with the same 12 hues and dark / normal / light variants.
4. The exact FFmpeg palette graph: video `fps → Lanczos scale`; seed `neighbor scale`; vertical stack; `palettegen=reserve_transparent=0:stats_mode=full`. No explicit `max_colors` is passed, matching the old FFmpeg default.
5. RGB888-to-RGB565 conversion by bit shifting, with palette entries written big-endian.
6. Per-pixel nearest-palette selection using the old squared RGB888 Euclidean distance. NumPy accelerates the operation while preserving the first-index tie rule.
7. The video filter `fps → Lanczos scale → hqdn3d`.
8. The old delta rule: the previous index buffer starts as all zeroes; unchanged indices become SKIP packets; changed pixels are grouped into same-index DATA runs.
9. The old short (1–63) and long (up to 16,383) packet headers and big-endian 16-bit lengths.
10. A big-endian uint16 packet-stream size before every frame.

The old C program accumulated all encoded video in RAM. This Python port writes each completed frame to a temporary output file as it goes, then atomically renames it. That changes memory usage and failure handling, but not the emitted legacy format or frame packet algorithm. The Python port also refuses a frame whose packet stream exceeds the legacy uint16 length field, rather than silently wrapping it.

## Requirements

- Python 3.10+
- NumPy
- FFmpeg and FFprobe in PATH

On Arch/CachyOS:

```bash
sudo pacman -S ffmpeg python-numpy
```

## Usage

The defaults match the original C program: maximum dimension 80 and 5 FPS.

```bash
python3 apps/cpv-player/tools/legacy_converter/convert.py input.mp4
```

By default, the output filename is the complete input filename plus `.cpv`, as in the old tool. For example, `clip.mp4` becomes `clip.mp4.cpv`.

To target the same maximum dimension and frame rate used by a comparison:

```bash
python3 apps/cpv-player/tools/legacy_converter/convert.py input.mp4 \
    -max_size 132 \
    -fps 5 \
    --output apps/cpv-player/tools/legacy_converter/output-legacy.cpv
```

The old format preserves aspect ratio and sets only a maximum dimension. It does not accept independent width/height values, letterbox, or support dimensions larger than 255 pixels.

## Tests

```bash
python3 -m unittest discover \
    -s apps/cpv-player/tools/legacy_converter \
    -p 'test_*.py' -v
```

The tests cover seed generation, header layout, short/long RLE packets, exact palette matching, packet round trips, and (when FFmpeg is installed) a short end-to-end conversion followed by decoding every legacy frame.

## Comparing with CPV v1.3

Use the exact same source and target maximum dimension/FPS in both tools. Remember that the legacy converter uses one aspect-ratio-preserving maximum dimension, whereas CPV v1.3 accepts explicit width and height.

For a 132-pixel maximum dimension and 5 FPS:

```bash
python3 apps/cpv-player/tools/legacy_converter/convert.py input.mp4 \
    -max_size 132 -fps 5 \
    --output legacy-132.cpv

python3 apps/cpv-player/tools/convert.py input.mp4 \
    --output modern-132x74.cpv \
    --width 132 --height 74 --fps 5 \
    --palette-quality 100 --preprocess-quality 100
```

The second command is an example only. For a fair comparison, choose the modern palette/preprocessing settings you want to evaluate. Compare output bytes, conversion time, and visual quality separately.

**Playback compatibility:** the modern CPV v1.3 host player does not read this legacy `CP` container. Use the old calculator player or the legacy SDL host player to preview the result.
